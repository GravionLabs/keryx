# keryx — Working in this repository

keryx is a local event bus, Attention API and PR gate for Claude Code and OpenCode sessions (see [README.md](README.md)).

## Layout

```
packages/keryx/            @gravionlabs/keryx: CLI and server, bin `keryx`
packages/keryx-opencode/   @gravionlabs/keryx-opencode: OpenCode plugin, no server dependencies
.github/workflows/         ci.yml (PRs into release/next), release.yml (main → GitHub Release + npm), issues.yml, release-branch.yml
.github/ISSUE_TEMPLATE/    epic, feature, pbi, task, bug (as in apm-hub)
```

TypeScript (strict, ESM, Node >= 22), pnpm workspace, Vitest, Biome. Unit tests sit next to the code as `<name>.test.ts`.

## Commands

```sh
pnpm install
pnpm run check      # verify command: build, typecheck, lint, test (the CI jobs)
pnpm run format     # Biome, writes
pnpm vitest run <path>
```

## Conventions

- Work on branches `<type>/<nr>-<slug>` from `release/next`; PRs target `release/next`. Commits are conventional: `<type>: <description> (#<nr>)`.
- Issue titles start with the level: `[Epic]`, `[Feature]`, `[PBI]`, `[Task]`, `[Bug]`.
- Both packages share one version, set at release from GitVersion (`GitVersion.yml`); the `version` in the package.json files is a placeholder. `CHANGELOG.md` is generated by git-cliff (`cliff.toml`) on release; do not edit it by hand.
